# 교육 관리 앱

부서원이 본인 이름을 선택해 수료증을 제출하고, 관리자가 승인·보완 요청을 처리하는 교육 관리 앱입니다. **Cloudflare Workers + D1 + Workers KV로 운영 중**이며, 기존 GitHub Pages 주소도 운영 앱으로 연결됩니다.

부서원 이름 순서는 **번호 직접 입력**으로 편집하고, 과장·4개 팀 구성은 **조직도 편집**에서 관리합니다. 최신 운영 반영 상태와 배포·검증 내역은 [최종 배포 상태](docs/최종배포_진행상태.md)에서 확인할 수 있습니다.

## 접속 주소

| 화면 | 운영 주소 | 기존 주소 — 운영 화면으로 자동 이동 |
| --- | --- | --- |
| 부서원 교육 안내·수료증 제출 | [부서원 화면](https://edu-status-v2.antae98.workers.dev/edustatus_all.html) | [기존 부서원 주소](https://vvvis-ai.github.io/edu-status-2026/edustatus_all.html) |
| 관리자 | [관리자 화면](https://edu-status-v2.antae98.workers.dev/edustatus_admin.html) | [기존 관리자 주소](https://vvvis-ai.github.io/edu-status-2026/edustatus_admin.html) |

관리자 화면은 관리자 비밀번호로 로그인합니다.

## 주요 기능

- **부서원:** 본인 이름 선택, 기간별 교육·이수 상태 조회, PDF·사진 수료증 제출과 보완 후 재제출.
- **교육·검토:** 교육 등록·수정·복제·공개·보관, 대상자·면제 설정, 수료증 미리보기와 승인·보완 요청.
- **명단:** 부서원 등록·수정·전출 처리, 인사이력 조회, 교육 안내 페이지의 이름 표시 순서와 과장·4개 팀 조직도 편집.
- **내보내기:** 교육별 최신 수료증 ZIP과 이수현황 XLSX 다운로드. 재제출 이전 파일과 검토 이력도 보존합니다.
- **감사 기록:** 개별 PDF 미리보기·다운로드와 ZIP에 포함된 파일별 요청을 추적합니다. 부서원의 이름 선택은 본인 미확인으로 구분합니다.
- **보관·파기:** 원본 PDF를 교육연도 12월 31일까지 보관하고 다음 해부터 확인·승인 후 파기 대상으로 검토합니다. 자동 삭제는 수행하지 않습니다. [보관·파기 절차](docs/수료증_보관파기절차.md)를 확인하세요.

### 이름 표시 순서를 번호로 바꾸기

1. 관리자 페이지를 새로고침하고 **부서원 관리 → 이름 순서 편집**을 엽니다.
2. 옮길 사람의 순서 번호를 입력하고 **Enter**를 누르거나 다른 곳을 선택합니다. 예를 들어 28번을 2번으로 바꾸면 한 번에 2번째로 이동하고, 나머지 번호는 자동으로 조정됩니다.
3. **이 순서 저장**을 누릅니다. 부서원 교육 안내 페이지를 새로고침하면 저장한 순서가 반영됩니다.

번호는 재직 부서원 수 범위의 정수로 입력합니다. **취소**는 저장 없이 닫고, **최신 순서 불러오기**는 편집 중인 내용을 버리고 저장된 순서와 명단을 가져옵니다. 순서는 서버에 보관되어 다른 PC에서도 동일하게 표시됩니다. 신규 부서원은 마지막에 추가되고 전출자는 공개 이름 목록에서 제외됩니다.

### 과장과 4개 팀 조직도 배치하기

1. 관리자 페이지를 새로고침하고 **부서원 관리 → 조직도 편집**을 엽니다.
2. 과장을 선택하고 4개 팀 이름을 입력합니다. 과장은 미지정으로 둘 수 있으며 팀 이름은 서로 다르게 입력합니다.
3. 각 부서원의 조직도 배치에서 해당 팀을 선택합니다. 처음 설정할 때 **팀 배치 대기**에 표시된 인원은 관리자가 직접 배치합니다. 아직 정하지 않은 인원은 그대로 둘 수 있습니다.
4. **저장 전 미리보기**에서 과장·팀 구성과 배치 대기 인원을 확인하고 **조직도 저장**을 누릅니다.
5. 부서원 교육 안내 페이지를 새로고침해 저장한 조직도를 확인합니다.

팀 안에서는 기존 **이름 순서 편집**의 번호 순서를 따릅니다. 신규 부서원은 팀 배치 대기에 표시되고 전출자는 조직도에서 제외됩니다. 조직도 배치는 부서원 관리에 기록된 팀·직급·인사이력이나 교육·이수 기록을 바꾸지 않습니다. **취소**하면 저장하지 않으며, 다른 관리자가 조직도나 재직 명단을 변경한 경우에는 **최신 조직도 불러오기** 후 다시 편집합니다.

## 운영 구성

| 구성 | 역할 |
| --- | --- |
| Cloudflare Workers | 웹 화면·공통 API·관리자 세션 처리 |
| D1 | 교육·부서원·제출·검토·이수·감사 이력과 이름 표시 순서·조직도 배치 저장 |
| Workers KV (`FILES_KV`) | 제출한 수료증 원본 파일 저장 |
| GitHub Pages | 기존 주소를 Worker의 해당 화면으로 연결 |

현재 파일 저장소는 **Workers KV**이며 R2 활성화는 필요하지 않습니다. 재제출한 이전 파일도 보존되므로 전체 이력이 저장 용량에 누적됩니다. KV의 파일 반영은 지역에 따라 지연될 수 있습니다. 한도·반영 지연·백업·이관 절차는 [운영안내](docs/운영안내.md)를 참고하세요.

## 로컬 실행

Node.js 24 이상에서 실행합니다. 새 체크아웃은 공개 가상 데이터로 초기화합니다.

```powershell
npm ci
npm run init:demo
npm start
```

- 부서원: http://127.0.0.1:3198/edustatus_all.html
- 관리자: http://127.0.0.1:3198/edustatus_admin.html
- 생성된 관리자 비밀번호: 이 PC의 `.dev.vars`에서 확인
- 로컬 DB·수료증: `.edu-data/`에 영구 보관
- 종료: `Ctrl+C`

이미 `.dev.vars`, `server/seed.json`, `.edu-data`가 있는 PC에서는 `npm start` 또는 `실행_교육관리앱.bat`로 이어서 실행합니다. `init:demo`는 기존 seed·secret 파일을 덮어쓰지 않습니다. 실제 명단·이수 스냅샷·수료증·비밀번호는 저장소에 포함하지 않습니다.

## 검증과 후속 배포

현재 자동 테스트 **97개**와 구문 검사를 통과했습니다. 조직도 배치의 입력 검증·동시 저장·명단 변경 충돌과 기존 기록 보존을 확인합니다. 기존 번호 입력 순서 편집은 가상 직원 28명으로 번호 이동·입력 검증·취소·저장·새로고침 후 유지·공개 목록 반영을 검증했고, 해당 운영 배포 전후 기존 교육·부서원·이수·제출 기록이 동일함을 대조했습니다. 기능별 운영 반영 여부는 [최종 배포 상태](docs/최종배포_진행상태.md)를 확인하세요.

```powershell
npm run check
npm test
npm run build
npm run cf:types
npm run deploy:dry-run
```

Node 서버는 SQLite와 로컬 파일을 사용하며 운영 D1/KV와 별도로 실행됩니다. 두 서버가 같은 API 코드를 공유합니다. `build`는 허용된 웹 파일과 보안헤더만 `web-dist`에 만들고, `deploy:dry-run`은 업로드 없이 번들·설정을 검사합니다.

운영 계정과 D1/KV 연결을 확인한 기존 배포 환경에서는 다음 명령으로 Worker를 갱신합니다.

```powershell
npm run deploy
```

`deploy`는 빌드 후 로컬 `.dev.vars`의 서버 secret을 Git에서 제외되는 `.dev.vars.production.json`에 준비해 같은 배포에 설정합니다. 비밀번호에 특수문자가 있어도 값이 그대로 전달됩니다. 운영 갱신에는 기존 운영용 `.dev.vars`를 사용합니다. `init:demo`가 생성한 비밀번호·세션 키는 로컬 시험용입니다. 기존 운영 DB에 초기 이관 SQL을 다시 적용하지 않습니다. 다른 계정에 새로 설치할 때는 해당 계정의 Worker·D1·KV를 마련하고 `wrangler.jsonc`를 변경한 뒤 [운영안내](docs/운영안내.md)의 신규 설치 절차를 따릅니다.

로컬 Workers의 스키마·가상 seed 준비, 비공개 이관 SQL, 백업·복구, 배포 절차는 [운영안내](docs/운영안내.md)를 참고하세요.

## GitHub Pages와 API

현재 앱 화면과 `/api`는 같은 Worker 주소에서 실행됩니다. GitHub Pages에는 기존 주소를 연결하는 HTML만 게시합니다.

공개 `deployment.json`에는 현재 `workerOrigin`이 설정되어 있습니다. `main`에 푸시하면 Pages workflow가 `npm run build:pages`로 연결 페이지 3개를 생성해 게시합니다. **GitHub에 소스를 푸시하는 것과 Worker 앱 배포는 별개**이며, 앱 변경은 위의 `npm run deploy`로 반영합니다. 주소가 바뀌면 검증한 origin을 `deployment.json`에 갱신합니다. 자세한 구성은 [Pages 연결안내](docs/Pages_연결안내.md)를 참고하세요.

## 기존 수료증 추출 도구

`★교육수료증_자동추출_엑셀변환기.html`은 수료증에서 정보를 읽어 엑셀로 취합하는 별도 도구입니다. 같은 폴더의 `certificate-parser.js`, `certificate-ocr.js`, `vendor/` PDF 엔진을 사용합니다. XLSX·OCR·글꼴 라이브러리는 외부 CDN을 사용하므로 해당 기능에는 인터넷 연결이 필요합니다. PDF 엔진 재생성은 `npm run build:pdf`입니다.

CLI는 `npm run convert` 또는 `실행_수료증_엑셀추출.bat`로 실행합니다. 현재 폴더와 일부 하위 폴더의 수료증을 찾아 CSV를 만듭니다. 교육 관리 앱의 정적 빌드에는 이 별도 도구와 원본 수료증을 넣지 않습니다.
