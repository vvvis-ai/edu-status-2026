# 교육 관리 앱 검증 결과 · 2026-10-27

주요 기능 구현 후 남아 있던 통합 검증과 배포 준비를 완료했습니다. 실제 서비스 배포는 운영 환경 결정 전입니다. 기존 운영 API에 쓰기 요청을 보내지 않았고, 시험 데이터는 별도 가상 저장소에만 생성했습니다.

실제 이관 데이터는 교육 11개·부서원 28명·기존 이수 205건·새 제출 0건입니다. `server/seed.json`과 `.edu-data/education.sqlite`는 전날 저장한 스냅샷과 SHA-256이 모두 일치했습니다.

## 수정한 문제

- 보관 교육이 부서원 이수율에만 포함되던 집계 차이를 수정했습니다. 공개된 진행 교육에서 면제·대상 아님을 제외하는 계산을 공통으로 사용합니다.
- 교육 행의 대상 인원도 수동 처리 상태를 반영하도록 통일했습니다.
- 부서원 수정창에 인사 변경 이력을 추가했습니다. 관리자 전용 이력 API는 대시보드 감사로그 최근 500건 제한과 별개로 해당 직원의 전체 이력을 반환합니다.
- 부서원·관리자 미리보기를 권한 확인 후 Blob URL로 통일했습니다. 파일 API의 sandbox CSP는 보존하며, 이미지 로드 실패 안내와 다운로드 대안을 제공합니다.
- 로컬 서버가 파일 전용 CSP를 덮어쓰던 문제와 루트 경로의 immutable redirect 헤더 오류를 수정했습니다.
- 저장 결과 크기 또는 저장소 head가 원본과 다르면 접수를 거부하고 이번 업로드 파일만 정리합니다. 이전 제출·검토·감사 이력은 보존합니다.
- ZIP 엔트리의 Windows 역슬래시 경로·드라이브 접두사·NUL 파일명을 거부합니다.
- 실행·검사·빌드·전체 테스트 스크립트, 가상 초기화, 빈 D1 초기 SQL 생성, 운영 문서와 binding 타입을 정리했습니다.
- 실제 seed·secret·DB·백업을 저장소와 정적 빌드에서 제외합니다. 기존 파서 테스트의 개인 PDF·비공개 백업 의존을 제거하고 fixture를 가상 문서로 교체했습니다.

## 실제 런타임·브라우저 검증

- Node 가상 서버: 교육 임시저장→수정→공개→부서원 반영, 월별 교육, 택1 과목 안내, 이름 선택.
- 브라우저 메모리에서 만든 합성 PDF/사진으로 파일 선택·드롭, PDF 실제 렌더링, 사진 로드, 손상 사진의 실패 안내, DRM 파일 거부를 확인했습니다.
- 제출→보완 요청→부서원 사유 표시→재제출→승인, 최신·이전 제출 이력 보존을 확인했습니다.
- Workers의 실제 로컬 D1/R2 런타임에서 PDF 원본 바이트 보존, 다른 사람의 파일 접근 거부, 버전 충돌과 과거 제출본 검토 거부를 확인했습니다.
- Workers 브라우저에서 PDF 제출→관리자 PDF 실제 렌더링→승인→교육별 승인 ZIP→이수 현황 XLSX를 확인했습니다.
- 브라우저가 다운로드용으로 생성한 실제 Blob의 내용을 검사했습니다. 승인 ZIP은 한글 경로와 648바이트 합성 PDF 원본을 포함했고 CRC가 일치했습니다. XLSX는 6개 OOXML 파트와 4개 행을 포함하며, 화면과 같은 상태·대상 수·이수율을 기록했습니다.
- 부서원 등록→팀 변경·전출→전출자 조회→변경 전후 인사이력, 교육 복제→보관 교육 조회를 확인했습니다.
- Workers API 응답과 관리자 브라우저에서 예상하지 않은 콘솔·페이지 오류는 없었습니다. 시험 중 의도적으로 발생시킨 손상 이미지·DRM 차단은 정상 안내로 처리됐습니다.

## 로컬 PDF 저장의 제약

이 PC의 기관 보안 프로그램이 로컬 디스크에 저장한 합성 PDF도 DRM 파일로 다시 변환했습니다. 이때 저장 크기가 원본과 달라져 미리보기·ZIP이 중단되는 현상을 확인했습니다. 저장 직후 감지되는 변화는 접수 실패로 처리하도록 수정했습니다. 이후에 보안 프로그램이 변환하는 경우까지 앱이 원본 보존을 보장할 수는 없습니다.

기관에서 허용하는 저장·보안 처리 방법을 확인하기 전에는 이 PC의 로컬 PDF 저장을 운영 검증 완료로 간주하지 않습니다. 보안 해제나 보안 설정 변경을 수행하지 않았습니다. 별도 Workers D1/R2 시험에서는 원본 보존과 다운로드를 검증했습니다.
