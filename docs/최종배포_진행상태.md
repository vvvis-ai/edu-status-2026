# 최종 배포 진행 상태 · 2026-10-27

사용자의 최종 작업 지시에 따라 실제 배포 연결을 진행했습니다. 앱과 기존 주소 연결 코드의 자동 테스트는 55개 모두 통과했습니다.

## 완료

- 필요한 Cloudflare 로그인 권한 갱신 확인.
- 전용 D1 `edu-status-v2` 생성(APAC) 및 스키마 적용. 현재 DB에는 테이블 구조만 있으며 실제 명단은 아직 이관하지 않았습니다.
- `wrangler.jsonc`에 실제 D1 ID와 배포 계정을 연결했습니다.
- 기존 운영 API와 공개 HTML을 GET으로 재대조했습니다. 교육 11개·부서원 28명·이수 205건이며 전날 대비 변경 0건입니다.
- 최신 이관용 seed·초기 SQL은 비공개 `.verification/edu-release/`에 준비했습니다. 기존 seed·로컬 DB는 유지합니다.
- GitHub 기존 main HEAD와 Pages 설정을 확인했습니다. 현재 main/root 게시이며 저장소 관리 권한이 있습니다.
- 기존 두 화면 주소와 index를 새 Worker로 연결하는 별도 Pages 빌드·workflow를 추가했습니다. 실제 Worker origin을 확인한 뒤 공개 `deployment.json`에 기록합니다.

## 현재 외부 의존 단계

Cloudflare R2 API가 `Please enable R2 through the Cloudflare Dashboard`(10042)를 반환했습니다. 계정의 R2가 비활성화되어 수료증 저장 버킷을 생성할 수 없습니다.

R2 시작에는 대시보드의 구독 등록 절차가 필요하며, 결제정보·이용 동의는 계정 소유자가 처리해야 합니다. 무료 제공량 초과 시 과금될 수 있습니다. 현재 작업에서 결제정보 입력·구독 등록·약관 동의는 수행하지 않았습니다.

## R2 활성화 후 이어서 진행할 순서

1. `wrangler r2 bucket list`로 활성화를 확인하고 전용 비공개 `edu-status-v2-certificates` 버킷을 생성합니다.
2. 최신 운영 GET 결과를 다시 대조합니다. 생성한 전용 D1이 비어 있는지 확인하고 비공개 초기 SQL을 적용합니다. 교육·명단·이수 집합까지 대조합니다.
3. `npm run deploy`로 코드와 `.dev.vars`의 서버 secret을 같은 배포에 설정합니다. 파일 값은 명령행·로그·저장소에 출력하지 않습니다.
4. 배포된 origin에서 공개 조회·관리자 로그인·파일 비공개 경로 차단과 이관 결과를 확인합니다. 실제 직원 기록에 시험 제출·검토를 하지 않습니다.
5. 확인한 origin으로 `deployment.json`을 작성하고 `npm run build:pages`를 실행합니다.
6. GitHub Pages source를 Actions로 전환한 후 최종 소스를 main에 반영하여 연결 페이지를 게시합니다. Worker 확인 전에는 기존 Pages 서비스 진입을 전환하지 않습니다.
7. 기존 부서원·관리자 주소의 실제 이동, 새 주소의 화면·API·세션·다운로드를 확인하고 최종 접속 주소·배포 버전·커밋을 기록합니다.

원격 기존 운영 API 쓰기·기존 데이터 삭제는 수행하지 않습니다. 비공개 리소스와 버킷을 공개 저장소로 게시하지 않으며 버킷의 공개 접근도 활성화하지 않습니다.

참고: [R2 시작 절차](https://developers.cloudflare.com/r2/get-started/), [R2 무료 제공량과 과금](https://developers.cloudflare.com/r2/pricing/).
