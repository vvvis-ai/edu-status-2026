# 수료증 원본 보관·파기 절차

## 보관 원칙

PDF는 이름·생년월일을 포함한 **제출 원본 그대로** 보관합니다. 앱에서 생년월일을 지우거나 PDF 내용을 바꾸지 않습니다. 조회·다운로드 권한과 파일별 요청 기록으로 접근을 관리합니다.

보관 종료일은 **업로드한 날짜가 아닌 교육에 설정된 연도**의 12월 31일입니다. 한국 시간으로 그 날까지 보관하고, 다음 해 1월 1일부터 파기 검토 대상으로 삼습니다.

| 교육연도 | 보관 종료일 | 파기 검토 시작일 |
| --- | --- | --- |
| 2026년 | 2026-12-31 23:59:59, 한국 시간 | 2027-01-01 |
| 2027년 | 2027-12-31 23:59:59, 한국 시간 | 2028-01-01 |

예를 들어 2026년 교육의 파일을 2027년에 늦게 제출해도 보관기간이 새로 시작되지는 않습니다. 교육연도가 잘못 등록되어 있다면 먼저 정확한 연도로 정정하고 대상목록을 다시 확인합니다. 재제출 이전 원본도 같은 교육연도를 적용하며 최신 승인본만 골라 파기하지 않습니다.

이 기준은 사용자가 정한 앱 운영 방침입니다. 기관의 기록관리 기준이나 감사·분쟁 등으로 다른 보존 근거가 있는 자료는 승인 담당자가 근거와 범위를 확인해 예외 처리합니다.

## 역할과 책임

| 역할 | 담당 업무 |
| --- | --- |
| 교육 관리자 | 대상목록 작성, 운영 저장소·로컬·다운로드·백업 사본 조사, 파기 실행 요청과 결과 확인 |
| 승인 담당자 | 교육연도·수량·보존 예외·파기 범위를 검토하고 실행 전에 승인 |
| 파기 작업 담당자 | 승인된 목록에 한해 영구 파기를 수행하고 저장소별 결과와 잔여 사본을 기록 |

실제 담당자와 승인권자는 부서에서 지정합니다. 공용 관리자 비밀번호 또는 화면에서 선택한 이름만으로 실제 작업자를 식별했다고 간주하지 않습니다.

## 연초 처리 순서

1. **대상 확정:** 전년도까지 보관이 끝난 교육의 파일 전체를 조사합니다. 운영 KV의 최신·이전 제출본, 로컬 `.edu-data` 사본, 내려받은 PDF·ZIP, 공유 폴더, 이관·복원용 백업을 함께 확인합니다. 반출·전달한 사본이 있으면 담당자에게 정리를 요청합니다.
2. **예외 검토:** 감사·분쟁·법정 보존 등 추가 보관 근거가 있는 파일은 임의로 지우지 않습니다. 파일 ID, 근거, 승인자, 연장 종료일 또는 재검토일을 예외 대장에 남깁니다. 단순히 "나중에 필요할 수 있음"만으로 무기한 보존하지 않습니다.
3. **실행 전 승인:** 대상 교육연도, 파일 ID 목록, 파일 수·용량, 대상 저장소·사본, 제외 근거, 작업 담당자와 예정일을 승인 담당자에게 확인받습니다. 대상목록 작성은 승인이나 파기 완료를 뜻하지 않습니다.
4. **승인 범위의 영구 파기:** 해당 교육의 추가 제출과 원본 제공을 중지한 뒤 승인된 파일 키만 삭제합니다. D1의 파일명·첨부 연결 등 관련 개인정보 메타데이터, 로컬 사본, ZIP·다운로드·백업 사본도 함께 정리합니다. 교육 이수 사실이나 감사 기록을 계속 보관할 별도 근거가 있다면 원본 PDF와 분리하고 필요한 최소 정보만 남깁니다. 실제 영구 파기는 별도의 승인된 운영 작업으로 수행합니다.
5. **재접근 불가 확인:** 일반 화면·직접 파일 경로·ZIP·운영 저장소·로컬·백업에서 승인 범위의 원본을 다시 제공하거나 복원하지 않는지 확인합니다. KV는 반영 지연이 있으므로 서버의 파일 제공 중지를 유지하면서 삭제 결과를 확인합니다. 제공자 백업이나 변경할 수 없는 백업에 잔여 사본이 있으면 처리 방식과 만료 예정일을 기록하고 완료 전까지 잔여 상태를 표시합니다.
6. **파기대장 작성:** 승인 및 결과를 최소한의 대장으로 남깁니다. 보관이 끝난 원본을 "파기 증빙" 명목으로 다시 첨부하지 않습니다.

파기대장에는 처리번호, 대상 교육연도·파일 ID, 개수·용량, 저장소·사본 범위, 파기 방법·일시, 담당자·승인자, 예외 및 잔여 사본 처리 결과를 남깁니다. 생년월일, PDF 내용, 비밀번호·세션 쿠키는 기록하지 않습니다. **열람 기록·파기대장·예외 대장의 보존기간은 원본 PDF의 연말 보관기간과 구분하여 기관 기준으로 별도 확정**합니다. 이 문서에서 임의의 법정 보존연수를 정하지 않습니다.

## 승인 전 대상목록 만들기

다음 도구는 D1의 교육연도와 파일 메타데이터를 읽어 대상목록을 만듭니다. **파일을 열거나 삭제하지 않으며, 자동 파기·예약 파기 기능도 없습니다.** 보존 예외나 운영 DB 밖의 로컬·ZIP·백업 사본을 자동 판정하지 않으므로 관리자의 후속 확인이 필요합니다.

```powershell
node scripts/prepare-certificate-disposal.mjs --help
node scripts/prepare-certificate-disposal.mjs --remote
```

`--remote`를 명시한 경우에만 현재 프로젝트 `wrangler.jsonc`의 운영 D1 `DB`를 조회합니다. 실행 전 로그인 계정과 DB 연결 대상을 확인합니다. 기본 기준일은 실행 시점의 한국 날짜입니다. 검토 기준일을 지정할 때는 `--as-of 2027-01-01`처럼 입력할 수 있으며, 미래 날짜로 만든 목록은 실제 파기일이 도래하기 전 실행 승인이 될 수 없습니다.

오프라인 검증은 `{ "courses": [{ "id": "c1", "year": 2026 }], "files": [...] }` 형태의 메타데이터 JSON을 비공개 폴더에 준비해 `--input`으로 전달합니다. 실제 원본 PDF를 입력하지 않습니다.

```powershell
node scripts/prepare-certificate-disposal.mjs --input .verification/disposal-metadata.json --as-of 2027-01-01
```

결과는 Git에서 제외되는 `.edu-exports/disposal/`의 `pending-disposal-*.json`에만 저장합니다. 파일별 항목은 파일 ID, 교육 ID, 부서원 ID, 저장 키, 크기, 교육연도, 보관 종료일로 제한하며 원본 파일명·이름·생년월일·PDF 내용은 넣지 않습니다. 실행 출력에는 개수와 결과 경로만 표시합니다. 식별번호·저장 키도 비공개로 관리하고 공개 GitHub·메신저에 올리지 않습니다.

연결된 교육연도, 파일 크기 또는 저장 키가 올바르지 않으면 산출을 중단합니다. 원본 자료를 먼저 확인·정정한 뒤 다시 생성합니다. 승인 시에는 생성 이후 파일이 추가되거나 교육연도가 바뀌지 않았는지도 다시 대조합니다.

## 파일별 열람 기록의 해석

앱의 `certificate_access_requested`는 미리보기·다운로드·ZIP에 포함된 **각 파일의 요청을 서버가 접수했다는 기록**입니다. 수신자가 실제로 모두 내려받거나 읽었다는 완료 증거는 아닙니다. 공용 관리자 인증과 이름 선택 세션을 구분해 기록하며, 부서원 이름 선택은 본인 인증이 되지 않았다는 점을 표시합니다. 기록에 원본 파일명·생년월일·PDF 내용·비밀번호·쿠키를 복사하지 않습니다.
