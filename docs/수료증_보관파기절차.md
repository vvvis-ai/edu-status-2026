# 수료증 원본 보관·파기 절차

## 보관 원칙

앱에 제출한 PDF와 사진은 교육 주최 부서에 전달하기 위한 확인용 사본입니다. 보관 중에는 이름·생년월일 등이 포함된 **제출 원본 그대로** 유지합니다. 조회·다운로드 권한과 파일별 요청 기록으로 접근을 관리합니다.

자동 파기의 보관 종료일은 **교육에 설정된 연도**의 12월 31일입니다. 한국 시간으로 다음 해 1월 1일 0시부터 추가 제출과 원본 제공을 종료합니다. 교육 주최 부서에 이미 전달한 사본은 그 전에 수동으로 일괄 파기할 수 있습니다.

| 교육연도 | 보관 종료일 | 자동 파기 시작일 |
| --- | --- | --- |
| 2026년 | 2026-12-31 23:59:59, 한국 시간 | 2027-01-01 |
| 2027년 | 2027-12-31 23:59:59, 한국 시간 | 2028-01-01 |

2026년 교육의 증빙을 2027년에 추가 접수해야 하는 경우에는 담당자에게 문의해 기관의 접수 경로를 이용합니다. 교육연도가 잘못 등록된 경우 보관기한이 오기 전에 정정합니다. 재제출 이전 원본에도 같은 교육연도를 적용합니다.

## 자동 파기와 운영 확인

Worker는 한국시간 매시 5분과 35분에 폐기 대상 파일을 최대 32개씩 처리합니다. PC에서 로컬 앱을 사용하는 경우에는 앱을 시작할 때와 이후 30분마다 해당 PC의 앱 저장소를 정리합니다. 저장소에서 파일을 삭제한 뒤 파일명과 첨부 연결을 정리하고, 이수 상태·수료일·검토 이력은 유지합니다. 서버가 작업 중 중단되거나 오류가 발생한 파일은 후속 실행에서 다시 처리합니다.

관리자 **감사 기록**의 **첨부파일 자동 파기**에서 처리 시각, 교육, 파일 ID를 확인합니다. 화면과 Worker 로그에 PDF 내용과 원본 파일명을 남기지 않습니다. 이 작업은 앱의 현재 저장소를 대상으로 합니다. 주최 부서에 전달한 자료, 내려받은 PDF·ZIP, 별도 백업은 각 저장 위치의 기관 기준에 따라 관리합니다.

운영 배포 전에 대상 첨부파일이 확인용 사본인지 확인합니다. 기록물 보존이나 감사·분쟁 등의 근거로 보존해야 할 파일은 기관이 지정한 저장소에 보존합니다. 자동 작업은 각 파일의 법정 보존 여부를 판정하지 않습니다.

## 관리자 수동 일괄 파기

1. 관리자 **수료증 검토**에서 연도·기간·검색어를 정한 뒤 **수료증 일괄 파기**를 엽니다. 조회 범위 안에서 교육을 좁혀 여러 제출본을 선택하거나, 표시된 제출본을 모두 선택할 수 있습니다. 표에는 부서원, 교육명, 접수 시각, 최신·이전 제출 구분, 첨부 개수가 표시됩니다. 확인·승인 상태와 관계없이 앱에서 열 수 있는 최신본과 이전 제출본을 선택할 수 있습니다.
2. **파기 대상 확인**을 누릅니다. 선택한 제출본만 표시되며 파기할 첨부 총수를 확인할 수 있습니다. 주최 부서에 증빙을 제출했는지 확인한 뒤 **○개 첨부파일 파기**를 누릅니다. 이 단계까지는 대상을 다시 선택하거나 취소할 수 있습니다.
3. 서버는 관리자 세션과 모든 선택 제출본의 버전을 확인합니다. 변경되었거나 이미 파기 중인 제출본이 한 건이라도 있으면 선택 전체를 다시 확인하도록 안내합니다. 유효한 요청은 한 번에 기록하고, 대상 파일은 즉시 미리보기·개별 다운로드·ZIP 제공에서 제외합니다.
4. 서버는 우선 최대 32개를 저장소에서 삭제하고, 성공한 파일의 파일명·첨부 연결을 정리합니다. 남은 파일과 재시도가 필요한 파일은 예약 작업에서 계속 처리합니다. 화면에는 완료 수와 대기 수를 표시합니다. 같은 교육의 선택하지 않은 제출본과 이수 기록은 계속 조회할 수 있습니다.
5. 관리자 **감사 기록 → 첨부파일 파기**에서 일괄 요청 시각·대상 수량과 각 파일의 파기 결과를 확인합니다. 요청 ID로 한 요청의 결과를 모아볼 수 있습니다. 요청자는 공용 관리자 계정으로 표시됩니다. 주최 부서에 전달했거나 이미 내려받은 사본은 각 저장 위치에서 관리합니다.

## 역할과 책임

| 역할 | 담당 업무 |
| --- | --- |
| 교육 관리자 | 교육 주최 부서에 제출 완료 확인, 앱의 파기 대상과 결과 확인 |
| 승인 담당자 | 자동 파기 범위와 별도 보존 대상 확인. 수동으로 파기할 사본은 대상과 방법 검토 |
| 파기 작업 담당자 | 앱 밖 다운로드·백업 사본을 관리하고 저장소별 결과와 잔여 사본 기록 |

실제 담당자와 승인권자는 부서에서 지정합니다. 공용 관리자 비밀번호 또는 화면에서 선택한 이름만으로 실제 작업자를 식별했다고 간주하지 않습니다.

## 연초 처리 순서

1. **대상 확인**. 주최 부서에 제출 완료된 사본의 교육연도와 범위를 확인합니다. 감사·분쟁·법정 보존 등 추가 보존 근거가 있는 파일은 보관기한 전에 기관의 공식 저장소에 보존하고 근거와 기한을 기록합니다.
2. **앱 처리 결과 확인**. 관리자 감사 기록에서 파기 결과를 확인합니다. 일반 화면·직접 파일 경로·ZIP에서 파일에 재접근할 수 없는지, KV 반영 이후 저장소에서 파일이 삭제됐는지 확인합니다.
3. **별도 사본 정리**. 내려받은 PDF·ZIP과 공유 폴더의 사본은 승인된 범위에서 정리합니다. 제공자 백업에 남은 데이터가 있으면 접근·복원 제한과 만료 예정일을 확인합니다.
4. **파기대장 작성**. 앱 처리 결과와 별도 사본의 처리·확인 내역을 기록합니다.

파기대장에는 처리번호, 대상 교육연도·파일 ID, 개수·용량, 저장소·사본 범위, 파기 방법·일시, 담당자·승인자, 예외 및 잔여 사본 처리 결과를 남깁니다. 생년월일, PDF 내용, 비밀번호·세션 쿠키는 기록하지 않습니다. **열람 기록·파기대장·예외 대장의 보존기간은 원본 PDF의 연말 보관기간과 구분하여 기관 기준으로 별도 확정**합니다. 이 문서에서 임의의 법정 보존연수를 정하지 않습니다.

## 승인 전 대상목록 만들기

다음 조회 전용 도구는 D1의 교육연도와 파일 메타데이터를 읽어 대상목록을 만듭니다. 운영 DB와 별도로 존재하는 로컬·ZIP·백업 사본은 담당자가 확인합니다.

```powershell
node scripts/prepare-certificate-disposal.mjs --help
node scripts/prepare-certificate-disposal.mjs --remote
```

`--remote`를 명시한 경우에만 현재 프로젝트 `wrangler.jsonc`의 운영 D1 `DB`를 조회합니다. 실행 전 로그인 계정과 DB 연결 대상을 확인합니다. 기본 기준일은 실행 시점의 한국 날짜입니다. 검토 기준일을 지정할 때는 `--as-of 2027-01-01`처럼 입력할 수 있으며, 미래 날짜로 만든 목록은 실제 파기일이 도래하기 전 실행 승인이 될 수 없습니다.

오프라인 검증은 `{ "courses": [{ "id": "c1", "year": 2026 }], "files": [...] }` 형태의 메타데이터 JSON을 비공개 폴더에 준비해 `--input`으로 전달합니다. 실제 원본 PDF를 입력하지 않습니다.

```powershell
node scripts/prepare-certificate-disposal.mjs --input .verification/disposal-metadata.json --as-of 2027-01-01
```

결과는 Git에서 제외되는 `.edu-exports/disposal/`의 `pending-disposal-*.json`에만 저장합니다. 파일별 항목은 파일 ID, 교육 ID, 부서원 ID, 저장 키, 크기, 교육연도, 보관 종료일로 제한하며 원본 파일명·이름·생년월일·PDF 내용은 넣지 않습니다. 실행 출력에는 개수와 결과 경로만 표시합니다. 식별번호·저장 키도 비공개로 관리하고 공개 GitHub·메신저에 올리지 않습니다.

연결된 교육연도, 파일 크기 또는 저장 키가 올바르지 않으면 산출을 중단합니다. 원본 자료를 먼저 확인·정정한 뒤 다시 생성합니다. 승인 시에는 생성 이후 파일이 추가되거나 교육연도가 바뀌지 않았는지도 다시 대조합니다.

## 파일별 열람 기록의 해석

앱의 `certificate_access_requested`는 미리보기·다운로드·ZIP에 포함된 **각 파일의 요청을 서버가 접수했다는 기록**입니다. 수신자가 실제로 모두 내려받거나 읽었다는 완료 증거는 아닙니다. 공용 관리자 인증과 이름 선택 세션을 구분해 기록하며, 부서원 이름 선택은 본인 인증이 되지 않았다는 점을 표시합니다. 기록에 원본 파일명·생년월일·PDF 내용·비밀번호·쿠키를 복사하지 않습니다.

참고: [운영안내](운영안내.md), [Cloudflare KV의 일관성과 반영 지연](https://developers.cloudflare.com/kv/concepts/how-kv-works/).
