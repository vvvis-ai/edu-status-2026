# 교육 관리 앱 실행·이관·배포 안내

이 앱은 부서원이 본인 이름을 선택해 수료증을 제출하고, 관리자가 승인 또는 보완 요청을 처리합니다. 교육·명단 관리, 승인된 최신 수료증 ZIP, 이수현황 XLSX를 제공합니다. 새 기능은 현재 로컬 검증 단계이며 기존 GitHub 사이트에는 배포되지 않았습니다.

## 현재 PC에서 이어서 실행

Node.js 24 이상을 사용합니다. 작업 폴더에서 다음 명령을 실행하거나 `실행_교육관리앱.bat`를 엽니다.

```powershell
npm start
```

- 부서원: http://127.0.0.1:3198/edustatus_all.html
- 관리자: http://127.0.0.1:3198/edustatus_admin.html
- 관리자 비밀번호·세션 키: 이 PC의 `.dev.vars`. 값을 문서·메신저·저장소에 복사하지 마세요.
- 실제 로컬 데이터: `.edu-data/education.sqlite`, 수료증 원본: `.edu-data/files/`.
- 종료: 서버 창에서 `Ctrl+C`. 데이터는 유지됩니다.

이 서버는 기본적으로 이 PC에서만 접속하는 `127.0.0.1`에 바인딩합니다. 실제 부서 배포의 인증·접속 범위·저장 위치는 별도로 결정해야 합니다.

이 PC의 2026-10-27 검증에서는 보안 프로그램이 로컬 디스크에 저장한 합성 PDF를 DRM 파일로 다시 변환했습니다. 이런 저장소에서는 업로드 이후에도 원본이 바뀔 수 있습니다. 앱은 저장 시 크기 변화를 감지하면 접수를 실패로 처리하며, 이후 변조된 파일 조회·ZIP도 중단합니다. 기관에서 허용하는 저장·보안 처리 방법을 확인한 뒤 PDF 원본 보존을 검증해야 합니다. 가상 Workers D1/R2 환경에서는 PDF 원본 바이트 보존을 확인했습니다. 자동 DRM 해제 기능은 제공하지 않습니다.

## 새 체크아웃에서 가상 데이터로 실행

```powershell
npm ci
npm run init:demo
npm start
```

`init:demo`는 `server/seed.example.json`을 비공개 `server/seed.json`으로 복사하고, 무작위 관리자 비밀번호와 세션 키를 `.dev.vars`에 만듭니다. 기존 파일과 기존 데이터베이스를 덮어쓰지 않습니다. 비밀번호는 `.dev.vars`에서 직접 확인하세요. 이 파일의 값은 따옴표 없이 `KEY=value` 형식으로 작성합니다.

예제 데이터는 가상직원 1명과 예시 교육 1개입니다. 모든 직원·교육·기록이 없는 상태로 시작하려면 새 설치에서 `server/seed.json`의 `courses`와 `members`를 빈 배열로 바꾼 후 최초 실행합니다. 이미 데이터가 있는 `.edu-data`를 지워서 초기화하지 마세요. 다른 시험은 `startLocalServer({dataDirectory: '별도 시험 폴더', seed: 가상데이터})`로 분리합니다.

## 초기 이관과 기존 기록 보존

현재 PC에는 기존 운영 API에서 읽기 전용으로 확보한 교육 11개, 부서원 28명, 이수 205건이 보존되어 있습니다. `server/seed.json`은 이 초기 스냅샷이며 실행 중 데이터는 `.edu-data`에 저장합니다. 로컬 서버는 교육·명단이 비어 있을 때만 초기 seed를 반영합니다. seed를 편집해도 이미 생성한 데이터베이스는 덮어쓰지 않습니다.

`scripts/prepare-edu-seed.mjs`는 기존 HTML 백업과 운영 API GET 조회로 초기 seed를 준비하는 기존 이관 도구입니다. 평소 실행할 필요가 없습니다. `--offline`은 HTML의 기본 명단을 사용하므로 최신 운영 현황과 다를 수 있습니다. 기존 운영 API에는 쓰기 요청을 보내지 않습니다. 기존 이수 추가 병합이 필요하면 관리자 API의 `import-legacy` 계약과 ID를 확인해 별도 검토합니다. 신규 직원은 기존 사람의 ID를 재사용하지 않습니다.

서버를 중지한 뒤 `.edu-data`, `server/seed.json`, `.dev.vars`를 함께 보관하면 로컬 복구에 사용할 수 있습니다. 실행 중에는 SQLite WAL 파일이 존재할 수 있으므로 DB 파일 하나만 복사하지 마세요. 복원은 별도 폴더에서 먼저 확인합니다. ZIP/XLSX는 제출 원본·전체 검토 이력·명단·인사이력 전체를 담는 백업이 아닙니다.

## 검증 명령

```powershell
npm run check
npm test
npm run build
npm run cf:types
npm run deploy:dry-run
```

`check`는 JavaScript 구문과 공개 예제 JSON을 확인합니다. `test`는 기존 수료증 파서 및 교육 API·상태·ZIP·XLSX 회귀 테스트를 실행합니다. `build`는 허용된 정적 파일과 보안헤더만 `web-dist`에 준비합니다. 비공개 seed·설정·로컬 DB·이관 원본은 빌드에 포함하지 않습니다. `cf:types`는 Wrangler 설정으로부터 DB/D1, FILES/R2, ASSETS 타입을 생성합니다. `deploy:dry-run`은 번들만 검증하고 업로드하지 않습니다. 구문 검사·번들 성공과 실제 서비스 검증은 별개입니다.

## Cloudflare 로컬 런타임 검증

로컬 Node 서버와 Workers는 같은 API 코드를 사용하지만 저장소 구현이 다릅니다. 로컬 Workers는 D1/R2 에뮬레이션을 사용하며 실제 운영 리소스와 연결하지 않습니다.

```powershell
npm run build
npm run cf:schema:local
npm run seed:sql
npx wrangler d1 execute DB --local --file .verification/edu-seed.sql
npm run cf:dev
```

`seed:sql`의 기본 입력은 공개 가상 example seed입니다. SQL 출력은 `.verification/edu-seed.sql`이고 기존 파일이 있으면 덮어쓰지 않습니다. 다시 준비할 때 `--output .verification/다른이름.sql`을 지정하세요. SQL은 대상 DB에 교육 또는 명단이 있으면 데이터를 삽입하지 않습니다. 실행 결과의 변경 건수를 확인하세요. 기존 상태를 교체·동기화하는 도구가 아닙니다.

```powershell
npm run seed:sql -- --seed server/seed.json --output .edu-exports/private-initial-seed.sql
```

위 명령은 실명 데이터가 포함된 비공개 초기 이관 SQL을 준비할 때만 사용합니다. 자동 업로드하지 않습니다. 기본 `.wrangler/state`는 Node의 `.edu-data`와 별개의 저장소입니다. `--persist-to`를 사용할 경우 schema·seed·dev 명령 모두 같은 경로를 지정해야 합니다.

## 실제 배포 전 남은 결정

최종 작업 지시에 따라 전용 D1 생성·스키마 적용과 배포 계정 연결을 완료했습니다. 실제 명단 이관과 Worker 배포는 R2 활성화 대기 상태입니다. 상세 진행 상태는 [최종배포 진행상태](최종배포_진행상태.md)를 확인하세요. 정적 GitHub Pages만으로는 수료증 저장·관리자 세션 API를 운영할 수 없습니다.

결정 후 담당자가 수행할 순서는 다음과 같습니다. 아래 원격 명령은 현재 검증 작업에서 실행하지 않았습니다.

1. 별도 시험용 Worker/D1/R2를 먼저 마련하고 `wrangler.jsonc`의 이름·ID를 연결합니다. 자동 생성이나 기존 운영 DB 연결을 추정해서 진행하지 않습니다.
2. D1 빈 DB에 `server/schema.sql`을 적용합니다. 신규 DB 여부와 백업을 확인한 뒤 비공개 초기 이관 SQL을 적용하고 교육·명단·기존 이수 건수를 대조합니다.
3. `wrangler secret put ADMIN_PASSWORD`, `wrangler secret put SESSION_SECRET`으로 서버 secret을 설정합니다. 실제 값을 명령행 인자나 공개 설정에 쓰지 않습니다.
4. `npm test`, `npm run deploy:dry-run`, 시험 런타임의 제출→보완→재제출→승인→ZIP→XLSX 흐름을 확인합니다.
5. 승인된 배포 대상에 `wrangler deploy`를 실행하고, 저장·권한·파일 다운로드·복원을 확인한 뒤 접속 주소를 전환합니다.

Wrangler의 `remote:false`는 로컬 개발시 리소스를 에뮬레이션하도록 지정합니다. 실제 배포에서 필요한 DB ID·버킷 이름의 연결을 대신하지 않습니다. PDF/사진 업로드는 기관에서 허용하는 보안 해제 절차를 먼저 거칩니다.

## 저장소에 포함하는 파일

공개 가능한 소스, 테스트, SQL 스키마, 예제 seed, 의존성 잠금파일, 운영 설명서, 생성된 binding 타입만 포함합니다. `.gitignore`는 실제 `server/seed.json`, `.dev.vars`, `.edu-data`, `.verification`, `.edu-exports`, 빌드 결과, SQLite 파일을 제외합니다. 이미 추적 중인 파일은 `.gitignore`만으로 제거되지 않으므로 커밋 전에 추적 목록과 staged diff를 확인하세요. 이전 원본 HTML에도 실명이나 기존 관리자 비밀번호가 들어 있을 수 있습니다.

참고: [Cloudflare Workers 모범 사례](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/), [정적 자산 HTML 경로 처리](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/), [Wrangler 명령](https://developers.cloudflare.com/workers/wrangler/commands/).

기존 GitHub Pages 주소를 실제 Worker로 연결할 때는 [Pages 연결안내](Pages_연결안내.md)의 공개 `deployment.json` 설정과 bridge 전용 게시 workflow를 사용합니다. Worker 검증 후 저장소 관리자가 publishing source를 전환합니다.
